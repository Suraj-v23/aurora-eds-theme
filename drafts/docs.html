Introduction

Aurora is a theme for AEM Edge Delivery Services. It is plain JavaScript and CSS on top of the official boilerplate, so there is nothing to compile and nothing to install at runtime. This guide covers how to set it up, restyle it and keep it fast. For Admin API recipes and block development, see the developer guide.

Tip. Use the Customize button at the bottom right to try the light and dark docs presets on this page.

Anything Adobe-specific, such as services, configuration and limits, is covered in the official documentation. This guide only describes what the theme itself does.

Quick start

Five steps take you from the template to a running local site.

  1. Open the repository on GitHub and choose Use this template to create your own copy.
  2. Install the AEM Code Sync GitHub app on that repository so pushes reach Edge Delivery.
  3. Connect a content source for your site. DA, Google Drive and SharePoint all work; the documentation walks through each one.
  4. Install the dev dependencies (linting only).
  5. Start the local server and open http://localhost:3000.
git clone https://github.com/<your-org>/<your-repo>.git
cd <your-repo>
npm i
npm run dev

npm run dev serves the demo pages from drafts/ together with your local code. To work against real previewed content instead, run the CLI without the folder options:

npx -y @adobe/aem-cli up

Project structure

Each block is a folder with one JavaScript file and one CSS file named after it. Global tokens and base styles live in styles/styles.css.

blocks/            one folder per block: name/name.js and name/name.css
  sidebar/         docs navigation, outline and page template
  fragment/        shared content; the only block others may import
icons/             24x24 SVG line icons used by :name: shortcodes
scripts/
  aem.js           vendored boilerplate runtime, never edit
  scripts.js       page decoration, auto-blocking, loading order
  utils.js         shared helpers: el, slugify, readJSON and more
  code.js          code block header, highlighting, copy button
  theme-panel.js   the Customize panel
styles/            styles.css (tokens, type, sections), fonts, lazy, panel
drafts/            local demo pages and nav fragments
tools/             build-demo.sh builds the GitHub Pages copy
head.html          scripts and stylesheet loaded on every page

Everything committed is served publicly. Anything that should not be, such as notes or build scripts, belongs in .hlxignore.

Presets

A preset is a set of variable overrides under [data-theme="name"]. Set data-theme on the html element or use the theme page metadata. Built in: ember (default), light, midnight, forest, mono, docs and docs-dark.

Fonts

No web fonts are downloaded. data-font switches between classic, modern, mono, rounded and editorial, each a different system font stack. Editorial also enlarges headings through --heading-scale.

Add your own preset

Add a block to styles/styles.css, then register its name in THEMES in scripts/utils.js so the customizer lists it. Only override what changes.

[data-theme="ocean"] {
  --background-color: #0b1a24;
  --surface-color: #112431;
  --light-color: #16303f;
  --text-color: #e6f1f7;
  --link-color: #38bdf8;
  --accent-color: #38bdf8;
  --on-accent: #04202e;
  --border-color: #23455a;
  --code-bg: #0a141b;
}

Customizer panel

The Customize button lets visitors pick a preset, an accent color, a font style and whether motion is on. Choices are stored in localStorage and validated against allow-lists before use. Hide the button on a page with the page metadata theme-panel set to off.

The navigation fragment is a list of links. A bold-only paragraph before a list becomes a group label. The template also builds an "On this page" outline from your h2 and h3 headings, adds hover anchors to them and appends previous and next links based on the order of page links in the navigation.

Spacing between sections comes from --section-pad. Two neighbouring sections without a background share a single gap, and so do two with the same background.

Icons

Write an icon name between colons in your document, for example :rocket:. Edge Delivery turns it into a span, and the theme loads /icons/rocket.svg and uses it as a mask, so the icon takes the color of the text around it. In the feature grid it sits in a tinted tile.

Included icons: palette, contrast, type, zap, layers, shield, code, search, layout, sparkles, rocket, book, terminal, copy, check, gauge, globe and puzzle.

Add your own

Drop a 24x24 SVG into icons/. Use stroke="currentColor" and no fixed fill colors so it follows the theme.

<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="none"
  stroke="currentColor" stroke-width="1.75" stroke-linecap="round" stroke-linejoin="round">
  <circle cx="12" cy="12" r="9"/><path d="m8 12 3 3 5-6"/>
</svg>

Search

The header search button (also / or Ctrl/Cmd+K) opens a dialog with live results. It first reads /query-index.json. If the site has no index it crawls the pages linked from the nav and docs fragments, which is how the demo works without any setup.

Add a query index

A query index lists every page with its title and description. Define it in a query.yaml file and upload it with the config service. See the indexing documentation for all options and the exact endpoint for your project.

version: 1
indices:
  site:
    include:
      - /**
    exclude:
      - /drafts/**
      - /**/fragments/**
    target: /query-index.json
    properties:
      title:
        select: head > meta[property="og:title"]
        value: attribute(el, "content")
      description:
        select: head > meta[name="description"]
        value: attribute(el, "content")
curl -X POST \
  "https://admin.hlx.page/config/$ORG/sites/$SITE/content/query.yaml" \
  -H "x-auth-token: $AEM_TOKEN" \
  -H "content-type: text/yaml" \
  --data-binary @query.yaml

Keep tokens out of files. $AEM_TOKEN is an environment variable. Never paste a real token into a document, commit or chat.

Performance rules

The theme is built to score well on Lighthouse out of the box. Keep it that way:

  • Keep the largest image or heading in the first section. It is the LCP element, so never lazy-load it.
  • Load blocks only on pages that use them. Each block is its own file; avoid importing one block from another.
  • Stay on system fonts. If you add a web font, load it from fonts.css after first paint and use font-display: swap.
  • Put anything non-essential, such as analytics, in delayed loading rather than eager.
  • Reserve space for images with width and height to avoid layout shift.
  • Keep total JavaScript small: no framework, no build step.

Accessibility checklist

  • One h1 per page and headings in order, never skipped for size.
  • Links inside paragraphs are underlined; navigation links are not. Do not rely on color alone for running text.
  • Every informative image has alt text; decorative images use empty alt.
  • Check contrast of any custom accent against the background; the customizer chooses dark or light text for you.
  • Every control works with the keyboard and shows a visible focus ring.
  • Motion respects the reduced-motion setting.
  • Buttons are real buttons or links, with a text label or aria-label.

Deploying the demo

The demo is a static copy of drafts/ built by tools/build-demo.sh. The GitHub Actions workflow in .github/workflows/pages.yaml runs it on every push to main and publishes the result to GitHub Pages. To build it yourself:

sh tools/build-demo.sh /your-repo-name
# open _site/index.html through any static server

A real project is served by Edge Delivery, not by this script.

Go live on your domain

On a production site your content is previewed on aem.page and published to aem.live. To serve it from your own domain, configure the production host for the site and point your DNS at the CDN as described in the go-live documentation. Merging to main ships code; content is published separately.
