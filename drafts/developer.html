Developer guide

Recipes for the Admin API, a walkthrough for building a block and a reference for the helpers in this repo. The command builder below only prints text: it never calls the Admin API and never asks for a token.

ref
main

Replace, not append. A POST to an access/admin.json config path replaces the whole list it targets. Read the current list first, add your change, then send the complete list back.

Authentication

Sign in at admin.hlx.page with the account that has access to your project, then read your profile to confirm who you are signed in as. Copy the session token as the Admin API documentation describes and keep it only in an environment variable.

export AEM_TOKEN="paste-your-token-here"
export ORG=your-org SITE=your-site REF=main

# who am I?
curl -s https://admin.hlx.page/profile -H "x-auth-token: $AEM_TOKEN"

Treat a token like a password. Never commit it, paste it into chat or a ticket, or write it into a script. Tokens expire: when calls return 401, sign in again and replace the variable.

Preview and publish one page

PAGE=docs   # path without a leading slash
BASE="https://admin.hlx.page"
curl -X POST "$BASE/preview/$ORG/$SITE/$REF/$PAGE" -H "x-auth-token: $AEM_TOKEN"
curl -X POST "$BASE/live/$ORG/$SITE/$REF/$PAGE"    -H "x-auth-token: $AEM_TOKEN"

Bulk publish with a loop

List one path per line in paths.txt. The loop stops on the first failed call so you can fix it before continuing.

BASE="https://admin.hlx.page"
while read -r p; do
  for step in preview live; do
    curl -sf -X POST "$BASE/$step/$ORG/$SITE/$REF/$p" \
      -H "x-auth-token: $AEM_TOKEN" -o /dev/null || { echo "failed: $step $p"; exit 1; }
  done
  echo "published $p"
done < paths.txt

Purge the cache

curl -X POST "https://admin.hlx.page/cache/$ORG/$SITE/$REF/$PAGE" -H "x-auth-token: $AEM_TOKEN"

Sync code after a push

The AEM Code Sync app normally does this for you. Run it by hand if a push did not arrive. End the path with * to sync a whole folder.

curl -X POST "https://admin.hlx.page/code/$ORG/$SITE/$REF/*" -H "x-auth-token: $AEM_TOKEN"

Check status

curl -s "https://admin.hlx.page/status/$ORG/$SITE/$REF/$PAGE" -H "x-auth-token: $AEM_TOKEN"

Read the site config

curl -s "https://admin.hlx.page/config/$ORG/sites/$SITE.json" -H "x-auth-token: $AEM_TOKEN"

List and add org users

Always read the list first. Writing to an access list replaces it, so send everything that should remain.

curl -s "https://admin.hlx.page/config/$ORG/users.json" -H "x-auth-token: $AEM_TOKEN"

curl -X POST "https://admin.hlx.page/config/$ORG/users.json" \
  -H "x-auth-token: $AEM_TOKEN" -H "Content-Type: application/json" \
  --data '{"email":"person@example.com","roles":["author"]}'

Update the index config

Upload your query.yaml (see the search section of the theme guide). Confirm the exact endpoint in the documentation.

curl -X POST "https://admin.hlx.page/config/$ORG/sites/$SITE/content/query.yaml" \
  -H "x-auth-token: $AEM_TOKEN" -H "content-type: text/yaml" --data-binary @query.yaml

Sitemap config

A sitemap is configured the same way, with a sitemap.yaml that points at the index. See the sitemap documentation for its format.

curl -X POST "https://admin.hlx.page/config/$ORG/sites/$SITE/content/sitemap.yaml" \
  -H "x-auth-token: $AEM_TOKEN" -H "content-type: text/yaml" --data-binary @sitemap.yaml

Building a block

A block is a folder in blocks/ with a JavaScript and a CSS file of the same name. The author writes a table; the page delivers it as nested divs, one per row and one per cell, and your decorate function turns that into the final markup.

Anatomy

blocks/facts/
  facts.js     export default function decorate(block)
  facts.css    every selector starts with .facts
  • Run curl localhost:3000/your-page.plain.html first to see the real markup you will receive.
  • Authors omit and add cells. Read rows and cells defensively and skip anything that is missing.
  • Scope all CSS to .facts. Names ending in -wrapper or -container are section classes.
  • Build elements with el() from scripts/utils.js. Strings become text nodes, never HTML.
  • Only fragment/fragment.js may be imported from another block; everything else shared goes in scripts/.

Example: facts

A two-column block that renders a definition list. First the authoring table:

| Facts   |                  |
| ------- | ---------------- |
| Runtime | Plain JavaScript |
| Build   | None             |

The script:

import { el } from '../../scripts/utils.js';

/* Facts: one row per fact. Cell 1 = label, cell 2 = value. */
export default function decorate(block) {
  const rows = [...block.children].map((row) => {
    const [label, value] = row.children;
    if (!label || !value) return null; // authors omit cells
    return [el('dt', null, label.textContent.trim()), el('dd', null, ...value.childNodes)];
  });
  block.replaceChildren(el('dl', null, rows.filter(Boolean)));
}

And the styles, using the theme tokens:

.facts dl {
  display: grid;
  grid-template-columns: max-content 1fr;
  gap: var(--space-2) var(--space-5);
  margin: 0;
}

.facts dt {
  color: var(--dark-color);
  font-weight: 600;
}

.facts dd {
  margin: 0;
}

@media (width < 600px) {
  .facts dl {
    grid-template-columns: 1fr;
  }
}

Loading order

Edge Delivery loads in three phases. Eager covers the first section and everything needed for the largest paint. Lazy loads the remaining sections, the header and footer, lazy-styles.css and fonts. Delayed, started from loadDelayed() in scripts.js, is for anything that can wait a few seconds. A block is loaded when its section loads, so a block that is not on a page costs nothing there.

Auto-blocking and fragments

buildAutoBlocks in scripts.js adds structure the author did not write: the breadcrumb when the breadcrumb metadata is on, the docs layout for the docs and library templates, and any link to a /fragments/ path, which is replaced by that fragment.

The isPage guard

Fragments are loaded by calling decorateMain on a detached main. Without a guard, a fragment would read the page metadata and build its own breadcrumb or docs layout, and a docs page that includes a fragment would recurse. Page-level auto blocks therefore run only when the element is the real document.querySelector('main').

import { loadFragment } from '../fragment/fragment.js';

const fragment = await loadFragment('/fragments/promo'); // a main element, or null
if (fragment) block.append(...fragment.children);

Local development

  • npm run dev serves drafts/ at / with your local code. npx -y @adobe/aem-cli up serves local code against previewed content.
  • Append .plain.html to any page URL to see the markup your block receives before any JavaScript runs.
  • Run npx -y @adobe/aem-cli up --help for flags such as the port or whether the browser opens.
  • Local demo pages write section styles as classes on the section div; real pages use Section Metadata.

Linting

npm run lint        # eslint and stylelint
npm run lint:fix    # apply safe fixes

Keep lint clean before opening a pull request. A pull request also needs a preview link in the form https://{branch}--{repo}--{owner}.aem.page/{path}.
